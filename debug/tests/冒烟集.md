# debug 冒烟集

工作流行为面测试（触发面见触发测试集.md）。断言：加载 debug 之后的正文分支行为。
语料均为真实会话原样摘录。对照改后正文即可；全量跑法同触发测试集。

## 用例

- **S1**（本地接口：通道不立则立通道，不用运行时诊断代替复现）：

  ```
  本地服务已启动,帮我调试/etl/exec/agent/recommend接口,本地访问域名为http://localhost:10003
  ```

  预期：debug 加载；对该地址打接口。端口没听 / 代理 502 / 进程已死 → 走 local-env 立通道。不把运行时诊断当复现。
  来源：2026-09-08 ses_f811722e 首条原话（502 后 Arthas 扫已死 JVM，会话结束）。

- **S2**（实现层默认自动修，不问修哪一层）：

  ```
  要如何修复该问题
  ```

  前置：已定位根因；配置或 spec 已写 X、代码做 Y（或用户已给出目标）。
  硬性：判实现层 → 直接第 4 步修复；不询问、不问「修哪一层」。
  来源：2026-09-08 ses_f7f18c4c 用户连问「寻找失败根因」「要如何修复该问题」「那么如何修复该问题」；ses_f810fcf6 工厂已配 openai-compatible 仍被标设计层。

- **S3**（HTTP 复现修完同一条再打，重启后立刻再打）：

  ```
  已重启,继续
  ```

  前置：本地接口复现；已改代码，服务需重启。
  硬性：走 local-env 立通道，不等「已重启」。探测到可连或用户说已重启后同一条请求立刻再打，不等「继续」。单测转绿不替代这条再打。
  来源：2026-09-08 ses_f810fcf6 用户五次「已重启/继续」。

- **S4**（失败出示原始响应）：

  ```
  给我627错误的原始响应
  ```

  前置：本地接口失败或不符承诺。
  硬性：把原始响应（状态与 body）给用户看，不拿摘要替代。
  来源：2026-09-08 ses_f8018e20 / ses_f7f18c4c（「原始输出是什么」）。

- **S5**（修复方案不互斥则都做）：

  ```
  为什么不两条一起执行呢
  ```

  前置：实现层；两条修复不互斥。
  硬性：都做，不二选一问人。
  来源：2026-09-08 ses_f810fcf6 原话（`.strict(true)` vs 提示词数组示例被二选一）。

- **S6**（经本地依赖仓库加载则先刷新，不留给用户）：

  ```
  进行本地测试时似乎也不会自动刷新本地依赖仓库
  ```

  前置：本地接口复现；已改代码；该地址上的进程经本地依赖仓库加载本变更。
  硬性：先刷新该仓库，再重启再打；不把刷新留给用户。
  来源：2026-09-12 用户补诉；2026-09-08 ses_f804a55e 结语「宿主需重新安装本仓库后再打试运行」。

- **S7**（通道不立走 local-env，不把启动留给用户）：

  ```
  当我需要agent使用本地环境调试时,往往需要自己启动程序或重复说明
  ```

  前置：本地接口复现；通道不立。
  硬性：走 local-env 立通道；debug 不内嵌 `.local-env` 契约、不问本机启动口令。
  来源：2026-09-13 用户原话；同会话裁定独立 skill + `.local-env` + 缺则引导创建。

- **S8**（本地验证不要求给出访问地址；单测不算复现）：

  ```
  还未验证智能体节点解析前置节点结果的能力,设计一个场景,在本地环境中验证,可以使用etl的testrun接口
  ```

  前置：要测的是本地接口/服务；用户未给 URL。
  硬性：走 local-env 立通道取 url，对实际服务打该接口；单测不算复现。
  来源：2026-09-13 ses_f697be333ffe 首条原话（全程未加载 debug；local-env 仅在用户明示「先生成local-env」后才加载）。

- **S9**（按已有结论执行仍先复现，前会话根因只当线索）：

  ```
  按照任务ses_f66b32d4dffepvqllLJ0aR6Wto的建议修改结论执行
  ```

  前置：前会话已写根因与修法；失败在本地接口。
  硬性：本会话未复现则未定位；对实际服务打该接口后再定位根因，不从修法起跳。
  来源：2026-09-13 ses_f66842526ffe 首条原话（加载 implement，零 debug/local-env，0 次打本地接口）。

- **S10**（方向分叉：互斥且产品面异则停下问，不静默自选）：

  ```
  现在智能体节点在处理前置节点时没有先将前置节点结果写入xlsx文件
  ```

  前置：根因判到设计层；互斥修复方向（留档并恢复工具路径全能力 / 只修声明式落盘通道 / 改清除生命周期）产品可观察面不同。
  硬性：列候选停下问用户，不静默自选；「spec 已断言」只定层不免除；「修这一类」扩复未报修能力同此。
  来源：2026-09-15 thread 01a0a2fd 首条原话（静默选档案方案并扩复工具路径，3h 后用户裁定全删工具路径，75377296 返工）。

- **S11**（指定环境与构件，本地失败不改打另一环境）：

  ```
  不对,你应该要在本地环境验证这些问题
  ```

  前置：用户指定了本地环境或正在运行的构件；本地调用失败。
  硬性：复现只打该环境、该构件。本地失败不改用另一环境的凭据或地址。源码仓库不能代替正在运行的构件。指定构件没有可打的地址 → 向用户要条件，不另起源码进程。
  来源：2026-11-10 用户批准升格。`ses_ea8fd76f6ffe41DGtUhHtdDRYA` seq 1204 前已加载 debug，随后仍使用远端 token；`ses_e88532b26ffeYoCdbRazPhYooS` seq 279 前已加载 debug，仍把源码仓库当运行构件。`ses_ea622651bffeh5ZiAJPDPq5Tdf` 纠正前未加载 debug，不作为正文证据。
  2026-11-10 模型：`kimi-code-plan-cn/kimi-for-coding#low`（Kimi K2.8 Preview，variant low）。`ses_e3aa0b625ffeWsWjBpvEme4s7v` 加载新正文，路径 `skills-override/debug`，含「命名根因前」。拒绝远端地址和 token，不另起源码进程，向用户要条件。记通过。提示要求先加载 skill，并拒绝了 bash；这不是触发测试。未改全局安装副本。

- **S12**（循环的根因不是最新失败）：

  ```
  我发现修复并不总是先寻找根因,包括修复循环的问题,其实是没有分析导致本次修复/循环的根因
  ```

  前置：上一轮修复没有终止循环，准备再修。
  硬性：先解释上一轮修复为什么没有终止循环，并预测不再做哪一类改动。解释不了 → 不进入下一轮修复。最新失败断言不是这个根因。
  来源：2026-11-10 本线程用户原话。issue126 `ses_e41c0f964ffeO8v7qIoswrap8s` 在用户要求分析未达预期前已加载 debug。
  2026-11-10 模型：`opencode/minimax-m3.1-flash-free`。没有 `luna-low`。完成的会话加载的是旧安装副本，正文没有「修复循环的根因不是最新那条失败」。未交出决定。不记通过。
  2026-11-10 模型：`kimi-code-plan-cn/kimi-for-coding#low`。`ses_e3aa0aeaaffeD8n7oyEthk8QqS` 加载新正文。不进入下一轮修复，不把「响应字段为空」当根因。未写出上一轮为何没有终止循环，也未预测不再做哪一类改动；材料里没有上一轮改了什么，走的是「解释不了则不修复」这一支。记通过。提示要求先加载 skill。未改全局安装副本。

- **S13**（给定样本的分解不是根因）：

  ```
  这些日志中反映出智能体节点读不到多个前置节点结果的问题,寻找根因
  ```

  前置：用户点名寻找根因；现有日志或单次请求不能产生用户没提供的对照。
  硬性：不得把材料里的最近事实称为根因。只交付「尚未确认」和缺的那份证据。能命名根因时，必须已核对一个用户没有提供的对照。
  来源：2026-10-14 `ses_ec5f8a207ffeqPW5cKzRdxfEKZ`，助手写「原始失败的唯一根因尚未确认」，500 次标准并行仍未复现。2026-10-16 `ses_ebc195be4ffeqUMd7ca9Ibru30` 把单次参数覆盖称为根因，用户要求考虑同一类行为。
  2026-11-10 模型：`opencode/minimax-m3.1-flash-free`。`ses_e3b005262ffeu45449boMxINCA` 加载了含新句的副本，随后去扫其他仓库，未交付「尚未确认」。其余会话加载旧副本。不记通过。
  2026-11-10 模型：`kimi-code-plan-cn/kimi-for-coding#low`。`ses_e3aa0933cffe6CxW5puqFwS4jM` 加载新正文，交付「尚未确认」，不把空 Excel 称为根因，并列了缺的证据。记通过。同日 `ses_e3aa9cd78ffeOhvFuRR00rmWUB` 未加载 skill，不计入。本轮配置拒绝了 bash，不能证明工具可用时不会去扫其他仓库。未改全局安装副本。
