# 资料研究

本 skill 守护一条主线：**每个可行动的结论都能回到拥有该事实的一手来源。** 研究结果是带来源的 Markdown 文件，不是会话中的无出处摘要。

## 核心工作流

### 1. 收口问题

写出研究问题、范围、目标版本或日期、需要支持的决策和明确不查的内容。问题清楚时直接开始，不为形式追问。

### 2. 选择一手来源

按以下顺序查找：

1. 当前仓库的代码、测试、配置和已有设计文档
2. 官方文档、规范原文、维护者源码和一手 API
3. 版本发布说明或官方 issue

二手文章只用来发现关键词，不能单独支持结论。当前事实记录版本、发布日期或访问日期。

### 3. 建立取证回路

资料较多或需要继续推进主任务时，派只读子代理分组调查。每个调查者只负责一个问题角度，返回来源、证据位置和未决项；主会话保留最终判断。

每条记录至少包含：主张、来源、来源位置、版本或日期、证据摘录或代码符号、置信状态。把事实、推断和未验证项分开。

### 4. 交叉核对

对关键结论至少做一次交叉核对：源码与文档、规范与实现、或两个独立的一手来源。发现冲突时保留冲突，说明各来源范围和采用理由，不静默选一个。

### 5. 写研究文件

遵循仓库已有的研究文档目录和格式。没有约定时写入 `docs/research/<topic>.md`，内容按以下顺序组织：问题与范围、结论、证据表、未决项、来源。每个可行动结论紧邻来源链接或 `file:line`。

### 6. 交付检查

逐条检查：结论是否能由来源支持、来源是否为一手、版本是否明确、推断是否标明、未决项是否列出。无法核实的内容写「未验证」和原因，不写成事实。

## 默认授权

- 直接执行：读取仓库和公开一手资料、派只读调查、起草研究文件
- 执行后告知：在仓库新增或更新研究文件
- 必须先确认：付费资料、登录账户、对外发布研究结论或修改生产代码
