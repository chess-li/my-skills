# AGENTS.md 编写与改造

## 意图锚点（每次使用前必读）

本 skill 守护一条主线：**AGENTS.md 只留代码表达不了的内容**——落后的根因不是没维护，是誊写了别处已是信源的东西。

护栏：

- 每条内容过尺子：改代码或权威文档会导致这条过时吗？会 → 不手写进文件
- 手写内容只三档：路由、约束、指针
- 引用不誊写：权威文档已有的断言给一行指针，不复制内容
- 路由具体到能分流；模型已知的通用工程常识不进文件

## 分路

| 现场 | 走 |
|---|---|
| 无文件，从零起草 | 起草工作流 |
| 已有文件落后、臃肿，或新增内容待审 | 改造工作流（纯评审停在分类清单） |

CLAUDE.md、.cursor/rules、copilot-instructions 等同类文件同一套纪律。

## 审计标准（两路共用）

**尺子**：逐条问——改代码、改构建配置、改权威文档，会导致这条内容过时吗？会 → 迁移或删除；不会 → 候选保留。

**正当三档**：

1. **路由**：什么任务或信号 → 加载什么 skill、查什么文档。具体到能真正分流（「改 skill → 先加载 skill-creator」）；「去看 docs/」不算路由。
2. **约束**：从代码推不出、但不写就会犯的纪律——冲突裁决、歧义处理、提交纪律、构建配置里读不出的操作口诀。
3. **指针**：权威文档位置，一行一条，不转述内容。

**过尺子必败**：

- 目录树、文件清单 → 代码自己能说，删
- 构建/测试命令 → 构建配置已声明的删；读不出的组合操作归约束
- 架构、行为、接口描述 → 信源在 spec/design/ARCHITECTURE，换指针
- 通用工程常识 → 模型已知，纯稀释
- 项目事实层（概览、技术栈、子项目索引）→ 不手写，走派生机制（bootstrap 标记区重算）

**刷新绑定**：三档内容也会变（新增 skill 忘了加路由）——把「检查 AGENTS.md」挂进结构性变更流程的收尾；项目无此类流程时在文件内写一行维护条款。

## 起草工作流

1. **收集事实**：读 README、构建配置、现有 docs 地图、skill 清单——只收集，不誊写
2. **提取差值**：筛出代码表达不了的三档内容；一项都没有 → 文件只放文档指针，不硬凑
3. **起草落盘**：按三档组织，每条过尺子；语言跟随项目已有文档
4. **自查**：逐条能归入三档；每条路由问「凭这条 agent 能分流吗」

产物：文件落盘，每条内容可归入三档之一。

## 改造工作流

1. **清单化**：现有文件逐段拆成内容项
2. **分类**：每项过尺子 → 留 / 迁（落权威文档后换指针）/ 删 / 派生化（挂进可重算机制）；项目用 bootstrap 时事实类内容迁标记区
3. **确认后重构**：出示分类清单，用户确认 → 留下的按三档重写；每项有交代（穷尽）
4. **绑刷新**：挂上「刷新绑定」

产物：分类清单（每项有去向）+ 重写后的文件。

## 授权

- 默认直接执行：读取、分析、出分类清单
- 执行后告知：新建文件
- 必须先确认：删除或迁移存量内容（出示分类清单，确认后落盘）；文件不在版本控制下时的一切删除性修改
