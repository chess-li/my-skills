# 设计文档维护

## 意图锚点（每次使用前必读）

本 skill 守护一条主线：**动手之前，把"怎么构建"固化在纸面上，并让 design 里的断言持续为真。** design 是 how 层变更的第一现场：改技术决策，先改 design。但 design 刻意保持薄：只记录值得固化的决策，不是代码的镜像。

改动护栏：
- 先判断要不要 design 再动笔：不触及已有 design 断言、也不产生值得固化的新技术决策的，直接干活
- 只写 how：what/why 与验收标准在 spec，引用不复制
- 决策归属范围定落点：归属单一上下文 → design；跨上下文或项目级 → ARCHITECTURE.md
- design 保持薄：只写"悄悄变了会有人受损"的技术决策
- 断言失真时只有两条路：决策仍被需要 → 更新它；已不重要 → 删掉它
- 上下文划分跟随 domains 文档；迁移跟随 domains 的变更时刻，不自行搬动

## 核心工作流

### 1. 入口判断

- 新改动：是否带来值得固化的技术决策（数据模型、对外契约、选型）？带来 → 进入流程
- 改已有技术：是否改变 design 或 ARCHITECTURE.md 已写过的断言？改变 → 先更新 design
- 对应上下文还没有 spec → 先走 spec skill 完成 what/why，再回来
- 皆否 → 退出流程，直接干活

### 2. 归属路由

逐条决策判定落点：

- 决策可在单一上下文内独立完成与变更 → `docs/contexts/<限界上下文>/<限界上下文>-design.md`
- 决策的变更需要跨上下文协同或影响全局（技术栈、部署、跨上下文契约） → 项目根目录 `ARCHITECTURE.md`

### 3. 读现状

- 读对应 spec（what/why 的来源）、已有 design 与 ARCHITECTURE.md
- 项目已有 `DOMAINS.md` → 先读，上下文划分跟随它

### 4. 写决策

- 每条：决策 + 约束/取舍理由（为什么选它、放弃了什么）
- 数据模型与对外契约：记自己一侧，引用对侧，不复制
- 代码可读出的细节（版本号、配置项、私有函数）不进 design

### 5. 边界自查

- 逐条过筛：这个决策悄悄变了，会有人受损吗？不会 → 删掉该断言
- design 不含 what/why；与 spec 断言不矛盾
- 跨上下文、design 与 ARCHITECTURE.md 之间无重复断言

### 6. 落盘

- 新建写入 `docs/contexts/<限界上下文>/<限界上下文>-design.md`（项目已有存放约定则跟随）；ARCHITECTURE.md 不存在时随首个项目级决策创建
- 更新在原文件就地修改断言，并追加一行变更历史
- 单文件大到难以维护时，在同目录按能力拆文件，命名 `<限界上下文>-design-<能力名>.md`，与 spec 拆分保持 1:1
- 语言跟随项目文档语言；无文档则跟随用户输入语言
- git 仓库：落盘后单独提交本次 design 变更，不与后续代码变更混合
- 完成后告知用户：design 已就绪，可进入实现

**design 文件模板**：

```markdown
# <上下文名> 设计

## <能力名>

### 技术决策
- <决策> —— <约束/取舍理由>

### 结构与契约
<数据模型、对外契约：记自己一侧，引用对侧>

## 变更历史
- YYYY-MM-DD 新建 / 变更 <什么>
```

**ARCHITECTURE.md 模板**：

```markdown
# ARCHITECTURE

## <主题名>

### 技术决策
- <决策> —— <约束/取舍理由>

## 变更历史
- YYYY-MM-DD 新建 / 变更 <什么>
```

## 冷启动

不要一次建成体系：上下文的第一个值得固化的决策出现时建 design 文件，第一个项目级决策出现时建 ARCHITECTURE.md；此前不预建空文件、不建索引。

## 完整示例（一次跨两层的需求）

- **现场**：用户说"订单加个过期缓存，用 Redis"
- **入口判断**：带来新技术决策 → 进入流程
- **归属**：Redis 选型与缓存结构归属订单上下文 → `docs/contexts/订单/订单-design.md`；"过期清理由消息队列统一触发"跨上下文 → `ARCHITECTURE.md`
- **写决策**：订单-design 记缓存数据结构、过期策略与取舍（一致性换性能）；ARCHITECTURE.md 记消息队列选型与理由
- **自查**：删掉"Redis 版本 ≥ 7"——依赖文件可读出，悄悄变了没人受损
- **落盘**：两份文件就地修改、追加变更历史，告知用户可进入实现
