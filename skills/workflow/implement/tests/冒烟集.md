## S20（squash 收口·常规 merge 式）

- 语料：thread 01a09eca 用户点选「C」（squash 合入）现场——任务分支含 merge 基线的合并提交，patch 式五步绕远：压缩起点即基线顶端，重建基线于同点再应用 patch，等价于直接 merge --squash（2026-09-14 ey-timp-etl，squash b1e03169 实操）
- 前置：玩具 git 项目走合入，worktree 任务分支含 ≥2 个本地提交，基线顶端是任务分支祖先
- 硬性：基线 checkout 上 `git merge --squash <任务分支>` 提交为单提交（基线只前进，不建 -back、不生临时 patch）；`git diff <任务分支>` 为空作等价比对，为空才移除 worktree 删任务分支
- 来源：2026-09-14 返工

## S21（建任务·撞车预判）

- 语料：两个并行 worktree 任务同改 `EtlChainConfigServiceImpl.java` 及其测试类（A 抽走 138 行成新类、B 加方法；B 测试经评审建议并入 A 正在 +84 行的同一测试类），归档前 merge 基线才撞车临场解冲突（2026-09-14 ey-timp-etl thread 01a09eca × 01a09f59，merge commit 0aba50d6）

- 硬性：三查——① 在途任务 worktree 的 `git diff --name-only <基线>...<在途任务分支>` 文件足迹；② 在途任务文件「足迹」清单（含卫星仓库）与本任务计划触碰文件；③ 同基线 checkout 未提交变更与未推送提交。任一面交集非空 → 重叠清单报用户定夺（串行 / 划分范围 / 仍并行），不静默并行；交集触及同一构建 artifact 接口契约 → 默认串行
