# interview 冒烟集

工作流行为面测试（触发面见触发测试集.md）。断言：加载 interview 之后的正文分支行为。
语料均为真实会话原样摘录；跑法同触发测试集。

## 用例

- **S1**（多义 → 列候选停下问）：

  ```
  现在skill的配置项有哪些
  ```

  预期：interview 加载；列出 ≥2 种会导向不同答案的解读；停下问，不直接给出某一种配置清单。
  来源：2026-09-02 ey-timp-lab ses_f9dff28fbfferh37TojOJTEyK5 首条原话（返工事件：自选 SKILL.md frontmatter，用户两轮纠正）。

- **S2**（一种解读 → 跳过）：

  ```
  将该配置的prefix修改为ey.skill.script.dependency
  ```

  预期：interview 不因多义提问（一种解读）；能力变更归 spec。
  来源：同会话第四条原话（前序已点明本项目扫描配置）。

- **S3**（事实先查，不当多义问）：

  ```
  我今天开了几个任务用来修复代码事实和文档不一致的问题,这些问题我觉得应该可以在开发流程或者review的时候避免
  ```

  预期：先搜今日任务/git log/代码；不把文档类别（spec/design/注释）当多义候选问人；查完若落点仍未决才问。
  来源：2026-09-04 返工（agent 先问 1/2/3/4，用户纠正「你应该搜寻今天的任务来判断」）。

- **S4**（路径多义 → 问，不因字面只点生成就当未指定）：

  ```
  生成的skillCode应该是30位以内且以字母开头,只包含数字字母下划线
  ```

  预期：列出 ≥2 种解读（只约束生成器 / 登记写入同样校验）；停下问 add 是否同样校验；不因「生成的」当未指定、不静默只改生成器。
  来源：2026-09-06 ey-timp-lab ses_f8b781b8fffe 首条原话（返工事件：先写出登记未定再访谈跳过）。

- **S5**（候选前提未实证 → 先验或标注，不当事实列项）：

  ```
  如何处理该问题 静态消息在枚举默认值与 throw 点字面量各维护一处
  ```

  预期：列候选前，候选依赖的框架行为（如枚举 getMsg 的非 Spring 可用性、convert 的格式化语义）与他服务契约（语言表同步）先实证；实证不了的标注为未验证前提随候选一并问，不把未验证前提当事实陈述。
  来源：2026-09-15 ey-timp-lab 线程 01a0a459 首条原话（返工事件：处方经裁定后被两个框架事实证伪，实验还原重开裁定；「错误码均无登记」断言被用户纠正）。
