# 访谈

## 意图锚点（每次使用前必读）

本 skill 守护一条主线：**多种合理解读或未决决策当前，列出候选停下问，不静默自选。**

护栏：

- 能列出 ≥2 个会导向不同产物或答案的解读 → 问
- 未指定的选择 → 走默认值，不问
- 事实自己查，决策才问
- 只访谈，不落断言文档

## 核心工作流

### 1. 判别

- 能自己查的事实先查完再判别（任务文件、git log、代码、仓库）。把本可查到的事实分类当成多义问人 → 不准
- 同一描述 ≥2 种合理解读且导向不同产物或答案 → 多义，进第 2 步
- 调用方交来未决决策 → 进第 2 步
- 未指定（缺选项但只有一条合理路径，或已有默认值）→ 走默认，返回调用方
- 目标轮廓未成形 → 回 <use-skill>spec</use-skill> 讨论出口
- 一种解读且决策已明 → 跳过，返回调用方

### 2. 列项

- 多义：每种解读一句话 + 若选它会做什么
- 未决决策：为什么做、给谁用、边界、边缘情形；调用方已列则用调用方的清单

### 3. 一次一问

一次一问，每问附推荐答案；多问齐发诱发敷衍。

### 4. 收敛返回

用户裁定后返回调用方；无调用方（开场问答）→ 按裁定的解读继续原任务。

## 完整示例（一次多义）

- **现场**：用户说"现在 skill 的配置项有哪些"
- **判别**：三解且产物不同——SKILL.md frontmatter / 解析器字段 / 本项目扫描配置
- **问**：你指哪一种？推荐本项目扫描配置（当前仓库是业务项目）
- **收敛**：用户点明本项目扫描配置 → 按该解读作答，不落文档

## 完整示例（事实当多义）

- **现场**：用户说"我今天开了几个任务用来修复代码事实和文档不一致"
- **判别**：文档类别（spec / design / 注释）写在今日任务与提交里，先搜再判；不是多义
- **做**：搜今日任务/git log，不把类别当候选问人；查完若落点仍未决才问
