# spec 冒烟集

工作流行为面测试（触发面见触发测试集.md）。断言：加载 spec 之后的正文分支行为与产物。
语料优先真实会话原样摘录；跑法同触发测试集（`opencode run --dir <目录> --title smoke-<ID> "<输入>"`），另观测会话产物（写了哪些文件、走了哪个分支、告知语是否发出）。

## 用例

- **S1**（愿景级输入 → 讨论出口）：

  ```
  我想要自建一个harness,拥有dsh的架构可塑性及可插拔性, 并拥有cindy和multica的多harness/agent编排沟通
  ```

  预期：spec 加载；告知「目标轮廓未成形：先讨论，不落文档」；产物为会话内决策清单（未决决策整批列出、每条附推荐方案）；零断言文档写入（无 docs/ 任何文件落盘）。
  来源：2026-09-01 opensource/harness 会话（ses_fa3ba5c7dffegxKznNY0MXaDbz）第二条原话，当日真实会话被 spec 文档流程吸收、用户 92 秒后纠正「我觉得可以先不从spec开始，而是先从讨论开始」（返工事件）；2026-09-01 讨论出口条款落地后建此用例。
  环境保真：原现场前序有 7 仓源码阅读与分析上下文。**单发跑法复现失败两次**（2026-09-02：空目录一次、目录含七仓符号链接+真实总结文件一次）——语境饥渴使开场分类被事实追问接管，spec 未加载、出口未到达（观察名单「干净会话回归覆盖不了依赖累积上下文的退化」又一实例）。有效跑法=两轮预置：目录预置七仓符号链接 + 真实分析总结文件（原会话产物），第一轮令其读总结，第二轮发原话输入。断言只钉分支判别（spec 加载 + 告知语 + 决策清单 + 零断言文档），不钉讨论内容质量。
