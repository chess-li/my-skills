## 应触发

- **P1**（完整详细需求文档，新能力未落纸面）：

  ```
  # 增加一个智能体节点,使用AgentScopeJava2来完成基于智能体的任务

  ## 节点配置: 在formData中需要配置
  1. agentCode(必填).通过IAgentDubboService.getAgentConfigByCode(新增)获取agentConfig(新增),agentConfig中包含modelCode和systemPrompt.通过IAiModelDubboService.getModelConfigByCode(新增)来获取modelConfig. modelConfig中包含用于模型连接的modeName,baseUrl,apiKey
  2. skillCodeList(可选,如果没有填写则只加载内置的skillConfig).这是在本节点中自定义需要使用的skill.通过ISkillDubboService.getSkillConfigListByCodes(新增)和IAgentDubboService.getBuildInSkillConfigList(新增)来获取自定义和内置skillConfigList.skillConfig中包含skillFileCode.需要使用IPlatformStorage来下载对应skill-zip
  3. userPrompt(必填).自定义如何处理本次任务,userPrompt允许完整的el解析.
  4. inputContract(可选,如果没有填写,那么本次执行无输入执行参数).输入参数合约table.输入合约中包含(key(输入名),description(输入参数描述)).通过getRequestParam(key)(这是一个需要新增的agent tool)获取对应的参数值
  5. outputContract(可选,如果没有填写,那么固定输出List.of()到下一节点). 输出参数合约table.输入合约中包含(key(输入名),description(输入参数描述)). 在调用模型时需要依据outputContract让模型返回结构化json数据(map结构).在获取到结构化json-map后,需要包装成List.of(output)输出到下一节点.
  6. fileBusId(可选,如果没有填写,则禁用writeFileToCode,该节点无法输出文件到系统中)

  ## 全局配置:
  ### 增加etl.agent.sandbox配置
  model: NONE(不使用sandbox)/DOCKER(使用docker)/K8S(使用k8s-agentsandbox)
  properties: 用来配置不同sandbox需要的配置信息

  ### 增加etl.agent.workspace.busId配置
  1. 通过com.ey.cn.ti.datamart.util.HybridFileableUtil#path(java.lang.String, java.lang.String)来获取workspace的parentPath,该path已经包含租户信息
  2. 实际的workspace为<parentPath>/<etl-code>/<etl-request-id>/<agent节点code>/

  ## 内置agentTool
  getRequestParam(key),用于从请求参数中获取对应值
  getPrevNodeList(),用于获取当前节点前的所有节点名
  getNodeResultByNode(nodeName),用于根据节点名来获取节点执行结果
  getFileByCode(fileCode),根据文件code获取文件到workspace中
  writeFileToCode(file),通过IPlatformStorage将文件写入对应的fileCode中

  ## 通用规则
  1. 智能体节点只能操作自己的workspace
  2. 智能体节点不能直接输出文件地址/文件blob,必须通过writeFileToCode将文件写入文件服务,只能向下输出fileCode
  3. 智能体节点的错误都不能隐藏,必须抛出异常中断ETL执行
  4. 智能体节点的过程日志中必须包含所有的思考/工具调用/mcp/skill等及对应的token usage.还必须包含总的token usage.智能体节点的异常也应该写入过程日志中
  5. 智能体节点只能获取inputContract中配置的参数或者前序节点的执行结果.
  6. 智能体节点只能向下输出outputContract中描述的结构
  ```
