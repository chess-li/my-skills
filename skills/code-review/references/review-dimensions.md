# 评审维度清单

评审标准的单一信源。消费方：code-review 派发完整评审时原文携带进派遣提示；implement 第 6 步评审自检闸逐项过。维度增删只改本文件。

## 1. 规格符合度

- 每条验收标准/意图有对应实现，无未请求的额外功能，无未请求的历史代码删除/修复
- 变更所涉 spec/design 断言仍为真
- issue 验证声称 = 命令 + 关键输出，逐条实际重跑比对（跑不了写明理由）；无运行支撑的标绿、输出矛盾、样本量虚报，视同未验证

## 2. 代码质量

- 命名、重复、复杂度、死代码（含方法体未引用的参数）
- 生产代码无测试专用的方法/字段/类型/分支；本任务导致既有生产代码退化为仅测试消费的（生产消费者被切走、旧入口仅剩测试调用），视同测试专用物——删除该入口或把测试迁到生产入口
- 无过度设计——每一层、抽象、扩展点（接口/钩子/配置项/预留位）能指出当前消费者
- 与同类代码的惯例一致性（结构/命名/错误处理）——实际读同类文件对比，不接受实现者自述

## 3. 测试

- 验证真实行为而非 mock、边界覆盖、全部通过
- 断言精确度（equals 而非 contains、无空断言）、无弱化或删除断言的痕迹
- 注册/装配面有验证覆盖：容器加载、依赖解析、路由/配置生效；含手工构造接线（A new B 并传入关键依赖的缝），不限容器注册
- 交付物（design/issue/注释/提交信息）中的「不可测/不可行」断言附隔离缝评估证据（静态 mock、容器替换、接口 mock、包装适配）；无证据视同断言不成立

## 4. 生产就绪

- 错误处理、迁移、安全
