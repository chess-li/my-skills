# issues 冒烟集

工作流行为面测试（触发面见触发测试集.md，待真实语料补建）。断言：加载 issues 之后的正文分支行为与产物。
语料均为真实会话原样摘录或现场取证。跑法同其他 skill 冒烟集（干净会话发输入，查 skill 加载记录并观测产物）。

## 用例

- **S1**（老布局 mega 任务文件迁入 → 拆分，不保留汇总形态）：

  ```
  我曾要求agent归档和合并历史issue,这是其结果 docs/issues
  ```

  前置：现场有 `docs/tasks/` 老任务文件，单文件承载多份已完成任务（ey-timp-etl 现场为 413 行汇总视图，跨多个能力章节抄录验收断言与证据）。
  硬性：归位迁入时拆为多份 issue（一份一事）、已完成即归档；不把原文件整体平移保留为「任务视图」；迁入后 `docs/issues/` 下只余 issue 文件与 archive/。
  来源：2026-09-25 ey-timp-etl 78063e87（`docs/tasks/智能体节点.md` 原样搬为 `docs/issues/智能体节点/任务视图.md`，0 内容改动）+ 当日用户投诉（返工事件）。

- **S2**（archive 只收 issue 文件）：

  前置：迁入/归档现场有设计文档、spike 验证报告与 issue 同目录。
  硬性：设计文档归 `docs/contexts/<限界上下文>/` 的 design（design skill 管辖）；spike/验证报告折入对应 issue 变更历史或 design；不入 archive。「已归档历史留原处」不覆盖非 issue 文件。
  来源：2026-09-25 ey-timp-etl 现场（`archive/01_*_issue_design.md`、`archive/01_*_spike1.md` 与 issue 文件混置）。

- **S3**（一份一事：相关 bug 不合并为一单）：

  前置：同一现场排查出两个相关 bug（同一 case、同一修复设计覆盖）。
  硬性：各立一份 issue，blockedBy 或正文互链；不因「两者联动、由同一设计修复」合并为一份。
  来源：2026-09-25 ey-timp-etl 01 号单标题「（Issue 1/2 合并）」——合并后归档检索无法再区分两个根因各自的闭环证据。

- **S4**（不建索引：迁移/归档合并不豁免）：

  前置：归档迁移或合并操作完成。
  硬性：不建 README/索引文件；frontier 递归扫描 issue frontmatter 即队列视图。迁移助手类文件操作完即删，不留现场。
  来源：2026-09-25 ey-timp-etl `docs/issues/智能体节点/README.md`（自称「issues 索引」，列级别/来源/摘要/状态表）。
