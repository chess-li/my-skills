# eli5 分层讲解

## 意图锚点

把一个主题讲到用户要的深度，不多不少。四档深度：了解（这是什么）→ 会用（解决真实场景）→ 所以然（为何如此）→ 改造（变更延伸）。档档是不同产物，不是同一讲解的详略版——「深入」的解法是升档，不是把本档讲得更长。

护栏：

- 未指明深度 → 默认「了解」档；信号横跨两档 → 列出两档问一句，不静默自选
- 高档讲解对前序档各一句带过，不展开复述
- 讲解止于「怎么改」；用户要动手改 → <use-skill>spec</use-skill> 管辖
- 用户反馈没懂 → 不原样重讲：降一档或换类比重来，补上被跳过的前置上下文；项目有 DOMAINS.md 时术语与类比从词条取

## 工作流

### 1. 判档

按请求信号判目标档：

| 信号 | 档 |
|---|---|
| 是什么 / 讲讲 / 介绍一下 / eli5 | 了解 |
| 怎么用 / 如何上手 / 如何用它做某事 | 会用 |
| 为什么 / 原理 / 怎么实现的 / 为何这样设计 | 所以然 |
| 怎么改 / 能不能扩展 / 基于它做别的 / 举一反三 | 改造 |

### 2. 读懂主题

讲解前先真懂，不靠猜：代码 → 读相关文件；报错 → 定位根因；概念 → 拆出核心组件。关键论断（用户会据此行动的那些）溯源一手资料并附引用，溯不到的明示凭记忆。客观信息不足 → 先补料再讲。

用户给了用途 → 产物锚定用途，场景取自用户的真实场景，不取泛化教科书场景。会用档且用途不明 → 问一句用在哪；其余档不问。

### 3. 按档产出

先讲它解决什么，再讲怎么做到。各档产物：

| 档 | 讲什么 | 默认产物 | 完成判据 |
|---|---|---|---|
| 了解 | 是什么、干什么用、一个核心类比 | HTML 图解页：大图少字 | 外行看完能一句话说清这是什么 |
| 会用 | 什么场景用它、最小上手路径、典型走查、常见坑 | 对话内场景指南 | 用户照做能在一个真实场景跑通 |
| 所以然 | 机制、设计取舍、与相邻方案对比 | 对话内讲解 | 用户能复述为什么是这样而不是那样 |
| 改造 | 可改的旋钮在哪、动哪个旋钮得什么效果、迁移到相邻场景的示例 | 对话内讲解 | 用户能指出要改成 X 该动哪里 |

用户指定产物载体时从用户；前序档各一句带过。

非了解档讲完落一张 HTML 参考卡：一页速查，只留结论、清单与术语，不重演讲解过程——供日后查阅。

技能类档（会用/改造）讲完检验兑现完成判据：让用户动手做一步，或答一两个检索问题，据回答给即时反馈。知识类档（了解/所以然）讲清即止，不加练习添负担。

### 4. 校准措辞

类比从受众已知的领域取；受众有专业背景时直接用术语。
