# bootstrap 冒烟集

每次改动 SKILL.md 正文后必跑；15 分钟内跑完。断言指向交付物价值，过程检查为辅。
在临时目录搭夹具项目跑，跑前记录夹具快照，跑后与快照 diff 验收。

## S1（空项目全量初始化）

- 夹具：全新单项目（一个 package.json + 少量源码，无任何文档）
- 语料：「在根项目及其子孙项目中生成AGENTS.md,根据项目事实生成DOMAINS.md和ARCHITECTURE.md」（2026-08-05 需求会话原话）
- 硬性：AGENTS.md 存在且全文在标记区内；区内所列命令真实可执行
- 硬性：DOMAINS.md 每条词条都能在代码/文档中找到对应概念；ARCHITECTURE.md 技术栈与 manifest 一致
- 硬性：codegraph 安装前先征求同意；除 3 份文档与 `.codegraph/` 外不新增其他文件

## S2（monorepo 首次初始化）

- 夹具：根 package.json + 两个子包（各有 manifest 与不同命令）
- 硬性：三份 AGENTS.md 各自事实正确（子包的命令是子包自己的，不是根的）
- 硬性：根 AGENTS.md 列出两个子包并引用各自 AGENTS.md；子包 AGENTS.md 引用根级 DOMAINS.md

## S3（已有 /init 产物接入）

- 夹具：项目含无标记区的 AGENTS.md（模拟自带 /init 生成，内容与待生成内容部分重复）
- 语料：「自带的init只能在根项目下生成,并且无法增量更新已有AGENTS.md」（同上会话原话）
- 硬性：标记区外原文逐字符保留；重复段落只在用户确认后删除；用户拒绝时原文与标记区并存且无内容丢失
- 硬性：不出现两份"子项目"并列段落（同一信息只在一处）

## S4（同步失实文档）

- 夹具：DOMAINS.md/ARCHITECTURE.md 含手写词条与 2 处预设过时事实
- 硬性：手写词条不被静默删改；所有改动先出清单经确认
- 硬性：清单覆盖全部预设失实点，漏报即失败

## S5（幂等重跑——历史痛点：自带 init 无法增量更新）

- 夹具：对 S1 已初始化项目连跑第二次
- 硬性：无任何文件变化；无重复标记区；不重复询问已同意事项
