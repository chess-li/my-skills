# 遗留变更安全回路

## 读取条件

变更区域满足任一条件时读取本文件：没有可信行为测试；当前行为不清楚；存在隐藏构造、全局状态、静态依赖或框架回调；正在迁移旧入口或消费者；或准备下结论说“不可测/此路不可行”。其他普通新代码沿用 `tdd` 正文，不增加这组步骤。

本文件补充 TDD 的安全网。`tdd` 仍拥有 RED/GREEN、最小实现、真实生产路径和测试断言；`debug` 仍拥有复现与根因；本回路不授权重写或顺手清理。

## 必须留下的产物

| 产物 | 内容 |
| --- | --- |
| 保留行为 | 本次必须继续成立的当前行为，包含外部可观察结果和已知边界 |
| 目标行为 | 本次明确要改变的行为；结构整理单独命名 |
| Characterization | 在改行为前捕获当前行为的测试或可重复记录；不把当前缺陷自动当作目标 |
| Change point | 要改变的调用、分支、数据流或入口 |
| 最小 seam | 能观察、替换或隔离阻塞依赖的最小缝；注明用途是 sensing、separation 或两者 |
| 验证证据 | 每个小步的命令、失败/通过输出和仍保留的断言面 |

## 安全回路

1. 写下保留行为和目标行为，确认“修复”没有把结构清理伪装成行为改变。
2. 读现有测试、调用者、装配和运行记录，标出没有保护的行为；不确定处先做 characterization。
3. 从 change point 向外追踪值、调用、字段、输出和协作者，选择能解决当前阻塞的最小 seam。
4. 若准备写“不可测”，先列静态 mock、容器替换、接口 mock、包装适配等隔离缝并记录为何采用或排除；没有评估不能下结论。
5. 在 seam 或 characterization 保护下按 TDD 写失败测试，确认失败原因是目标行为缺失，再写最小生产实现。
6. 每个小步验证后再继续；行为改动、结构重构和清理分开提交，暂时 seam 不能成为无消费者的永久抽象。
7. 回归保留行为和目标行为，确认旧入口没有只剩测试消费；到达本次目标后停止，新的 smell 另记。

## 不得推导的结论

- 没有单元测试不等于可以直接改；先找 characterization、集成入口或最小观测点。
- 测试难写不等于生产代码可以增加测试专用方法、字段、类型或分支。
- 一个 seam 失败不等于所有路径不可测；必须说明尝试过的隔离缝和证据。
- 遗留区域不等于允许顺手重写；只改变本次目标，并保持其他行为可核验。
