# implement 冒烟集

工作流产物约束；15 分钟内对照模板人工断言即可。触发面见 `触发测试集.md`。

## S1（前端对接·错误码对外取值）

- 语料：「我觉得生成的前端对接文档的错误码是有问题的,这份文档里的错误码应该是暴露给前端的错误信息,而不是代码内部的错误信息」（2026-09-01 ey-timp-lab 会话原话）
- 前置：任务归档刷新 `*-前端对接.md`
- 硬性：「码」列是接口对外暴露给前端的错误取值，不是内部枚举名或常量名
- 来源：2026-09-01 返工

## S2（前端对接·出参完整 JSON）

- 语料：「出参应该反映完整的json」（2026-09-01 同会话原话）
- 前置：同 S1
- 硬性：出参是完整响应 JSON 代码块，不是散文摘要（如「result 为 id」）
- 来源：2026-09-01 返工

## S3（squash 收口）

- 语料：「核对上周的任务,我总是会批准任务结束后合并commmit,我觉得这一项可以不再要求审批而是自动合并」（2026-09-07 用户原话）
- 前置：玩具 git 项目走归档，任务在基线分支产生从 spec 到归档 ≥2 个本地提交
- 硬性：任务分支合入基线后默认压缩为单个提交（执行后告知该序列，不询问）；走 patch 式五步——生成区间 patch（--binary）、基线分支改名 -back 保留、从压缩起点重新检出、应用 patch 提交单提交、新旧分支 diff 为空才删 -back；单提交序列不压；序列含已推送远端的提交则改写与强推须用户明示
- 来源：2026-09-07 用户裁定（上周 ey-timp-lab 归档后 reflog 连续 patch 式 squash 均批准）+ 2026-09-01 五步协议（原「询问」语料废止）

## S4（整洁·死参数）

- 语料：「修复这两个死代码问题… ShellCommandRules.java:143 record 的 embeddedScripts 是死参数」（2026-09-04 ses_f9446b0a7ffe 原话）
- 前置：本任务产出含方法签名
- 硬性：本任务产出的方法签名不含方法体未引用的参数
- 来源：2026-09-04 返工

## S5（归档前核对已有声称）

- 语料：「我今天开了几个任务用来修复代码事实和文档不一致的问题,这些问题我觉得应该可以在开发流程或者review的时候避免」（2026-09-04 用户原话）
- 前置：任务验收清单全绿，准备归档
- 硬性：归档前读任务文件引用的 spec 章节与对应 design 决策（不在 diff 里也要读），失真走偏差路由；本次改动所及类型/方法上的 javadoc/类注释行为事实与代码不一致则改注释或改代码；不把 design 写成代码镜像，不补写新注释
- 来源：2026-09-04 返工（ey-timp-lab c30e601 spec/javadoc/类注释三处失真；script-scan-log-cause shfmt 非零退出分级；7e20f55 解压写失败日志）

## S6（归档·删除本地任务分支）

- 语料：「两个本地的 skill-deps-query skill-mcp-whitelist 分支似乎没有删除」（2026-09-06 ses_f8b4637e3ffe 原话）
- 前置：git 仓库走归档（合入任务分支 + 移除 worktree）
- 硬性：移除 worktree 含删除本地任务分支；归档后 `git branch` 不含任务名
- 来源：2026-09-06 返工

## S7（Minor 不完成）

- 语料：「虽然评审的结果是minor,但我要求修复,应该视为任务未完成才对」（2026-09-07 用户原话）；同日 ses_f863478c 可合入后归档，用户再问遗留并要求修
- 前置：独立评审仅 Minor
- 硬性：不归档；Minor 默认自动修（不询问）后 scoped 重审；不得因 scoped 可合入归档
- 来源：2026-09-07 返工

## S8（合入前完整评审）

- 语料：「在合并/提交到基线分支前应该对工作分支/差异进行完整review 以避免scoped review无法发现完整问题」（2026-09-07 用户原话）
- 前置：修复循环已做 scoped 重审且无未处理发现，准备合入基线
- 硬性：合入基线前最近一次评审是工作分支相对基线的完整评审且无未处理发现；scoped 重审清零不够
- 来源：2026-09-07 返工

## S9（归档合并·提交与遗留询问）

- 语料：「审视上周的任务,我发现手动要求合并task archive后有时不会自动提交,也不会就遗留问题询问是否修复/完成」（2026-09-07 用户原话）
- 前置：用户发起同一 spec 多份归档合并
- 硬性：汇总写入后提交（git 仓库，执行后告知，不询问是否提交）；核对后仍成立的未完成/待办列出并问是否现在完成；仍成立的范围外问题留在汇总、不问；未批准不修
- 来源：2026-09-07 用户投诉（上周 ey-timp-lab：09-02 runtime-deps、09-03/04 agent-skills 汇总不问遗留）+ 2026-09-07 本会话审查（问句含范围外、单任务归档证据误入）
