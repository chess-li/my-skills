# 写作

## 意图锚点（每次使用前必读）

本 skill 守护一条主线：**读者用最少的阅读成本拿到最多的事实。** 语气默认：直接、紧凑、陈述、简单、易懂。

护栏：
- 准确先于文采：润色、改写不得增删事实
- 说不清的地方回去补内容，不用修辞掩盖
- 语言与体例跟随读者和项目既有同类文档

## 工作流

1. 定读者：谁读、读完做什么 → 定详略与语言
2. 搭骨架：先列标题与要点，再填段落
3. 成段：按下方词汇、语句、结构三张清单落笔
4. 通读：逐句问"删掉它读者损失什么"，无损失即删

## 词汇

**招募顺序**（选词先问哪里有现成词）：

1. **语义锚定用户**：用户给的事实与判断原样保留。措辞准确就直接用；口语化就等强度转写——只校准精度与语域（"不好使"→"偶发无响应"），不拔高程度（→"体验有待优化"即失真）；有数据就给数据（"有点慢"→"响应约 2 秒"）。意思拿不准 → 追问，不靠猜
2. **项目既有词汇**：术语表（DOMAINS.md 等）与同类文档已用的词；领域概念的命名裁定归 domains skill，此处只引用
3. **法律法规词汇**：强合规领域中法规定义的说法不可替换
4. **行业共识**
5. **社区共识**
6. **能够直接理解的词汇**垫底：无需解释即懂的日常小词；生僻词、大词、自造词是末位

**干净闸**：招来后词义须恰好等于要表达的，无夹带——"赋能""抓手"夹带官腔，"delve""seamless"夹带营销腔，"净""仅仅"夹带情绪。

- 一词到底：同一概念全文同一词；换近义词"求变化"制造的是歧义不是文采
- 修饰词默认删：形容词、副词删掉后含义不变 → 删

## 语句

- 一句一事，长句先拆
- 开场结尾不载客：首句直接给信息，停在最后一个事实上；"综上所述""希望对你有帮助""In conclusion""I hope this helps" 直接删
- 限定条件写成明确前提（"当 X 时"），不堆"可能/也许/某种程度上"
- 主动语态默认，被动仅用于施事者未知或不重要
- 结构由标题层级承担，不用"首先/其次/最后"与排比凑气势

## 结构

- 结论先行：段落首句是该段结论，章节首段是全章结论
- 标题承载信息：写"缓存失效的三种成因"，不写"概述"
- 列表只装真并列：各项同级、顺序可换才用列表；叙述与论证写成段落
- 一个事实只在一个位置陈述，他处引用

## 语言别条款

### 中文

- 标点全角；中文与英文、数字之间加半角空格
- 不写英文腔的中文：删冗余"作为"、泛滥被动，"的"字链超过两个即拆

### 英文

- Plain English：hedging 与 marketing 词（delve、leverage、utilize）换成具体小词
- 破折号克制：能用逗号、句号就不用 em-dash
- 对话式文本默认用 contractions
