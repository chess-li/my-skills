# writing 触发测试集

修改 description 后必跑。断言：干净会话中是否加载了 writing（`skill` 工具调用 name=writing）。
语料优先真实会话原样摘录；跑法：`opencode run --dir <空目录> --title trigger-<ID> "<输入>"`，再查会话 DB 的 skill 加载记录。

## 应触发

- **P1**（新文档）：`帮我写一份新成员 onboarding 文档`
- **P2**（改写）：`这段说明写得太绕了,帮我改清楚,意思别变`
- **P3**（英文）：`write the README for this repo`
- **P4**（口语半截）：`帮我把今天会议纪要整成个文档`

## 不应触发

- **N1**（邻近 skill：spec）：`给登录功能补一条验收标准写进 spec`
- **N2**（邻近 skill：domains）：`统一一下项目里"订单"和"工单"的叫法`
- **N3**（邻近 skill：skill-creator）：`帮我审查下 writing skill 的措辞`
- **N4**（代码任务）：`这个函数报错了帮我看看`
- **N5**（纯问答，无落盘文本）：`解释一下什么是幂等`

## 边界观察（不做硬性断言）

- **B1**（表述改写 vs 内容变更）：`design 文档里这段话表述不清,帮我改写下(不动技术决策)`
  writing 应触发；若同一请求要求补充技术决策，则归 design。记录实际行为供后续判断
- **B2**（skill 文件措辞，证据日志观察名单项）：`帮我改下 spec skill 正文,有几句话太绕`
  现行边界归 skill-creator；记录 writing 是否触发及产出质量，供"writing 是否管 SKILL.md"观察项取证
