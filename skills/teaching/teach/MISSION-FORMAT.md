# MISSION.md 格式

`MISSION.md` 在工作区根目录，记录用户学这个主题的**原因**。每个教学决策（接下来教什么、推哪些资源、设计什么练习）都可回溯到它。

## 模板

```md
# Mission：{主题}

## 为什么
{1–3 句。用户在追的具体现实目标：有了这项技能，工作/生活里什么会变？避免「为了理解 X」式抽象表述，追到底层结果。}

## 学会的样子
- {用户将能做到的一件具体、可观察的事}
- {另一件具体的事}
- {…}

## 约束
- {时间、预算、已有安排、学习偏好——一切限制教法的因素}

## 范围外
- {用户明确暂不追的相邻主题，保护最近发展区不被摊薄}
```

## 规则

- **一个工作区一个使命。** 想学两件不相干的事 = 两个工作区。
- **具体压倒抽象。**「十月跑完半马」胜过「变得更健康」；「给团队交付一个 Rust CLI」胜过「学 Rust」。
- **对含糊要顶回去。** 用户说不清为什么学 → 先访谈再写。坏使命比没使命更糟。
- **现实变了就修。** 使命会漂移：目标动了就更新此文件，别让过期使命继续指挥后续会话。
- **保持短。** 超过一屏的 MISSION.md 已不是指南针，是计划书。
