# TDD

## 意图锚点（每次使用前必读）

本 skill 守护一条主线：**没有先失败的测试，就没有生产代码。** 完成的定义是"测试通过且本轮实际观察到"，不是"代码写完了"。

纪律：

- 铁律：先写失败测试，再写刚好让它失败转通过的最小实现。实现代码先写了 → 删除，再按测试先行重写；不留作参考，不回看
- 最小实现含结构面：每一层、抽象、扩展点（接口/钩子/配置项/预留位）须能指出当前消费者；指不出 = 过度设计，不加
- 写与既有同类平行的代码（新 FormData、新枚举值、新组件）前，先读 2–3 个同类，对齐其结构/命名/错误处理模式；≥2 个一致实例才算惯例，个例不强制对齐
- 一次一个垂直切片：一个测试 → 最小实现 → 下一个测试。先批量写完全部测试再统一实现 = 违规
- 每次 RED 与 GREEN 都实际运行测试命令并读输出：RED 确认因功能缺失而失败（不是拼写错误）；GREEN 确认全部通过且无报错警告。"应该能过"、"刚才跑过"不算证据
- 期望值手工推导；用被测代码计算期望值 = 自己验证自己，恒真，禁止。断言真实行为；mock 的行为不设断言
- 断言写到最精确：equals 优先于 contains，完整值优先于片段，精确匹配优先于模糊匹配。断言变弱 = 保护变弱
- 测试失败时修实现，不改测试。想删断言、放宽匹配器、缩小用例范围的那一刻，正是实现未达标的信号——怀疑断言本身写错时向用户确认，确认后改断言也要说明理由
- 测试走生产真实发生的路径：真实入口、真实依赖、真实数据流。注册/装配面也是真实路径——组件向容器/框架的注册（bean 能否加载、依赖能否解析、路由/配置能否生效）必须有验证覆盖，只测单元逻辑不算验证了装配。不为测试在生产代码里添加仅供测试的方法/字段/类型/分支——想为测试开口子，是设计不可测的信号，改设计（如注入依赖），不加测试专用物
- 改完做一次变异自检：心里改动实现的一行，至少一个测试应随之失败；全不失败说明测试没保护行为
- 修 bug 先写复现 bug 的失败测试，再修
- 例外仅限原型、配置文件、生成代码；拿不准是否例外 → 问人
