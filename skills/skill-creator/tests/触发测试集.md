# skill-creator 触发测试集

修改 description 后必跑。断言：干净会话中是否加载了 skill-creator。

## 应触发

- **P1**（从零创建）：`我想从零创建一个新 skill,用于自动生成提交信息`
- **P2**（本会话类）：`根据现有经验总结一个 skill-creator,要能创建和审查 skill,对外发布`
- **P3**（迭代优化）：`这个 skill 上下文太臃肿了,帮我精简一下`
- **P4**（表现异常）：`domains skill 老是不触发,帮我看看`
- **P5**（补测试集）：`给 writing skill 补一套冒烟测试`

## 不应触发

- **N1**（邻近·writing）：`帮我把这段说明写清楚,意思别变`
- **N2**（邻近·domains）：`统一一下项目里"订单"和"工单"的叫法`
- **N3**（邻近·spec）：`给登录功能补一条验收标准写进 spec`
- **N4**（执行业务任务）：`用 tdd 给这个函数补测试`（应 tdd，不因"skill"字样误触）
- **N5**（纯问答）：`skill 和 prompt 有什么区别`

## 边界观察

- **B1**（改 skill 正文措辞）：`帮我改下 spec skill 正文,有几句话太绕`
  应 skill-creator；writing 不应抢（见 writing 负向边界与观察名单）
- **B2**（执行某 skill 所服务的任务）：`按 implement 把这条验收做完`
  应 implement，不因讨论 skill 名而触发 skill-creator
