# skill-creator 冒烟集

每次改动 SKILL.md 正文后必跑；15 分钟内跑完。断言指向交付物价值，过程检查为辅。

## S1（从零创建·model-invoked）

- 语料：「根据现有的skill经验,总结出一个用于创建/修改/审阅skill的skill-creator skill,我希望将该skill用于本项目并对外发布」（2026-08-19 本会话原话）
- 硬性：产出 SKILL.md，name 与目录一致；description 含本质能力 + 负向边界，不枚举用户说法
- 硬性：正文有可执行工作流（创建或分路），步骤锚定产物；创建分路不要求同期交付测试集
- 硬性：用户拿到后可按正文走完一次创建，无需再问"第一步做什么"

## S2（迭代·有返工证据）

- 语料：「用户反馈：AI 输出与文档充斥造词型黑话，解码成本高」（2026-08-04 返工事件原意，见 skill-证据日志）
- 前置：已有 skill 正文含只问"招募"不问副作用的选词原则
- 硬性：诊断落到措辞/选词机制层，而非只改几个词的表面替换
- 硬性：改动附带证据引用；有可观察的规则升格（如双闸），不是空提醒"注意用词"

## S3（无证据优化·应拦）

- 语料：「帮我优化一下这个 skill」
- 前置：目标 skill 冒烟通过、用户未报返工
- 硬性：不落地无证据正文改动；理论项进观察名单或等价物
- 硬性：若产出审查清单，阻断项与理论项分级可见

## S4（触发不准·改 description）

- 语料：「domains 在命名讨论里没触发」（类 2026-08-04 domains 欠触发）
- 硬性：先动 description 判别逻辑，不堆正文关键词冒充触发修复
- 硬性：改后有触发测试集或至少正/反例各一条可复跑

## S5（移植·机制不誊写）

- 语料：从他库 skill 提取"测试先行"类纪律并入本仓库 skill
- 硬性：合入文无源仓库路径/工具名/场景专名残留
- 硬性：能指出提取的是哪条机制（铁律/默认值/产物断言），不是整段粘贴
