# 测试质量

写测试与评审测试共用本文件。判据只写在这里。

写测试前读取全文并应用。评审派遣时原文携带本文件。不适用的项写明原因。

## 判据

- 验证生产中真实发生的行为，不验证 mock 的行为。期望值手工推导。用被测代码计算期望值，等于自己验证自己，禁止。
- 覆盖该行为的边界。测试必须实际运行并全部通过。没有运行记录的通过不算通过。
- 断言写到最精确：equals 优先于 contains，完整值优先于片段，精确匹配优先于模糊匹配。不用空断言。断言变弱等于保护变弱。
- 测试失败时修实现，不改测试来转绿。想删断言、放宽匹配器或缩小用例范围时，先向用户确认断言本身是否写错。确认后改断言也要说明理由。
- 删除或改写既有行为测试前，先清点断言面。被测行为仍存在的断言，等价迁回新位置和新形态。迁不回等于该行为已变更，停下向用户陈述，不静默丢断言面。
- 测试走生产真实入口、真实依赖和真实数据流。注册与装配面要有验证：容器加载、依赖解析、路由或配置生效，以及手工构造接线（A new B 并传入关键依赖）。只测单元逻辑不算验证了装配。测试从生产不再走的门进入，全绿不算覆盖。
- 本机能够启动的运行时依赖（真实存储、守护进程、集群、锁实现）另写本地集成测试，走生产路径打该运行时。默认构建不启动它，镜像或守护进程缺失不失败。启用命令与该运行时的已知限制写在测试旁。已知限制不是被测逻辑失败。默认套件通过不关闭只有这条测试能观察的行为；交付写明未跑的部分。
- 测试被环境型依赖卡住、且本机不能启动该运行时时，先枚举隔离缝：静态 mock、容器替换、接口 mock、包装适配。本机能够启动时，隔离缝不代替本地集成测试。未评估隔离缝时，「不可测」或「此路不可行」不成立。交付物里的这类断言没有隔离缝证据时，视同不成立。
- 扫描或枚举类守护测试必须自带非空自检：断言扫描器命中已知样例，结果集非空，元素加载失败要显式记录。扫描近空集时测试必须失败。
