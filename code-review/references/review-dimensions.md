# 评审维度清单

未按场景拆出的评审标准放在本文件。已拆出的场景不在本文件复述。

消费方：code-review 派发独立评审时原文携带本文件，并原文携带本文件指向的场景文件；implement 第 6 步自检按本轮范围逐项过本文件和场景文件。限定复审的未变范围引用前轮独立结论，不冒充本轮重新审过。只携带本文件、不携带场景文件，视同未携带已拆出的判据。

场景文件的判据只改该场景文件。未拆出的维度只改本文件。

## 1. 规格符合度

- 每条验收标准/意图有对应实现，无未请求的额外功能，无未请求的历史代码删除/修复
- 变更所涉 spec/design 断言仍为真
- issue 验证声称逐条核验；真实执行来源、独立重跑/复用与未验证处置只按 code-review 第 2 步

## 2. 代码质量

写代码与评审代码共用 [code-quality.md](code-quality.md)。判据只在该文件。

## 3. 测试

写测试与评审测试共用 [test-quality.md](test-quality.md)。判据只在该文件。

## 4. 生产就绪

- 错误处理、迁移、安全
- 变更涉及外部调用、异步任务、超时、重试、队列、复制或派生数据、迁移、容量边界，或可能出现未知成功时，读取 [失败契约参考](../../spec/references/failure-contract.md)，逐项对照 spec/design、代码和验证输出；不适用的字段写明原因，缺少证据写“未验证”

## 5. 交付状态与真实入口

- “已完成”“已提交”“工作树干净”“全部通过”等状态性断言有对应命令、退出码、关键输出和提交哈希；提交失败或仍有未解释的工作树/未跟踪文件时，结论必须是未完成或明确未提交
- HTML、CLI、脚本和其他非纯库交付物按真实入口 smoke；只做静态解析不等于交互、响应式、无障碍或运行时验证。无法运行时标“未验证”并说明缺口
