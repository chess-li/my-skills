# TDD

## 意图锚点（每次使用前必读）

本 skill 守护一条主线：**没有先失败的测试，就没有生产代码。** 完成的定义是"测试通过且本轮实际观察到"，不是"代码写完了"。

纪律：

- 入口路由：standalone 承接编码请求时，先走 spec skill 判管辖再回来——是否豁免由 spec 正文判定；自 implement 流程或 spec 判管辖后进入的，本条空满足
- 铁律：先写失败测试，再写刚好让它失败转通过的最小实现。实现代码先写了 → 删除，再按测试先行重写；不留作参考，不回看
- 测试质量：写测试前读取 [test-quality.md](../code-review/references/test-quality.md) 全文并应用。写测试与评审测试共用该文件。未读不得写测试。不适用的项写明原因。本 skill 不复述其中判据。测试失败、删改既有测试或声称不可测时，按该文件处理
- 代码质量：写生产代码前读取 [code-quality.md](../code-review/references/code-quality.md) 全文并应用。写代码与评审代码共用该文件。未读不得写。不适用的项写明原因。本 skill 不复述其中判据
- 失败契约：变更命中 [失败契约参考](../spec/references/failure-contract.md) 的读取条件时，写生产代码前读取全文。spec/design 已写字段要有失败测试，并实现进代码。缺用户可观察结果则停下，不在测试或实现里补语义。不适用的字段写明原因。未读不得写该边界的代码
- 无行为变化的改动（注释、格式、纯重命名）：仍加载本 skill；不要求新失败测试，但既有测试必须全绿方可动手、动手后必须仍全绿
- 一次一个垂直切片：一个测试 → 最小实现 → 下一个测试。先批量写完全部测试再统一实现 = 违规
- 每次 RED 与 GREEN 都实际运行测试命令并读输出：RED 确认因功能缺失而失败（不是拼写错误）；GREEN 确认全部通过且无报错警告。"应该能过"、"刚才跑过"不算证据
- 变更区域没有可信行为测试、当前行为不清楚、包含隐藏依赖或正在迁移旧入口时，读取 [遗留变更安全回路](references/legacy-change-safety.md)。先写保留行为与目标行为，做 characterization，选择最小 seam；该参考补充测试安全网，不替代本 skill 的 RED/GREEN。
- 改完做一次变异自检：心里改动实现的一行，至少一个测试应随之失败；全不失败说明测试没保护行为
- 修 bug 先写复现 bug 的失败测试，再修
- 跑测试前先读项目根 `.local-env/test`（可执行，跟随软链）。存在则用 `.local-env/test -- <本次测试命令>`，不重新探测本机 JDK、构建命令和守护进程。不存在，或按它执行因环境失败 → 立信道并探测一次；成功后把本机环境写入该文件。文件只设置本机环境并执行 `"$@"`，不写死测试选择器。本机路径不进仓库。local-env 不创建、不执行此文件。信道不成立（构建环境版本与项目要求不一致、未改动基线编译不通过、工作目录不正确）时，测试输出不算证据
- 同一命令第二次因环境/路径失败 → 停手，把本机环境写入 `.local-env/test`，不另写第二份包装脚本，不靠记忆第三次重试
- 同一测试同一失败现象第 2 次修复仍败 → 停下回读断言与 spec 原文再动手；第 3 次仍败 → 熔断：把现象与已试路径报用户定夺（含建议换更强模型重试），不第 4 次猜
- 写入共享本地状态（本地依赖仓库、全局缓存）即记账：写了什么、谁会读到旧物；模块间依赖优先在同一构建进程内解析（如 reactor 全量构建），不经共享仓库的中间态。已启动服务从该仓库加载本变更时，刷新该仓库除外（验证要它看见新物，不是测试信道）
- 例外仅限原型、配置文件、生成代码；拿不准是否例外 → 问人
