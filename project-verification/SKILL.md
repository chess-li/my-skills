# 项目验证

本 skill 守护一条主线：**把怎样操作这个应用并看出成功留在目标项目，而不是每次重新摸索。**

## 工作流

1. **盘点真实入口**
   记录产品入口、启动前提、动作驱动、结果观察、数据隔离、清理方法和已知限制。Web、CLI 或其他入口走该项目已有路径。不另造一套通用点击器。

2. **写首版地图**
   项目验证地图和项目专属 skill 写在目标项目，不写入本通用包。用户未指定路径时，写入 `docs/verification/项目验证地图.md` 和 `docs/verification/SKILL.md`。首版只收 3–5 个主要功能。每条使用下面的槽位。有 spec 则链接；没有则写缺失，不编造预期。

3. **环境不可用就停在条件**
   只记录缺少的运行条件。不写已运行证据，不改写产品预期。通道缺失时交 local-env，不在本 skill 里另起服务。

4. **先走通一个功能**
   环境可用时，实际执行其中一个功能，把可复现步骤留在地图。命令结果用 implement skill 目录的脚本记录：`python3 "<implement skill 目录>/scripts/run_evidence.py" run --root <被验证项目> --output <证据文件绝对路径> --criterion "<功能名>" -- <argv>`。证据放 `<主工作区>/.agent-artifacts/<任务>/<唯一运行标识>/`，Git 用登记的主 checkout，非 Git 用项目目录；首次创建前在该工作区 `.gitignore` 加 `/.agent-artifacts/` 并用 `git check-ignore` 核验，非 Git 跳过。地图只引用证据，不复制原始输出；清理槽位只覆盖本次创建的一次性数据，不删除共享父目录与历史证据。退出码 0 不表示产品预期已满足。

5. **维护时分开三种结论**
   - 文档漂移：地图与当前入口或观察方式不一致
   - 驱动缺口：地图仍对，但缺少可执行驱动
   - 产品回归：按地图执行后，观察与地图中的预期不符
   同一实时应用只由一个操作者控制。其他检查只读，或使用隔离数据。回归交 debug。极端界面数据交 break-ui。地图缺口不是回归。

## 授权

- 直接执行：只读盘点，起草地图
- 执行后告知：把地图和项目专属 skill 写入目标项目
- 必须先确认：修改产品代码，删除已有地图，操作共享生产数据
