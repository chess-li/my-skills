# 人工操作向导

本 skill 守护一条主线：**把必须由人完成的动作变成可暂停、可重跑、可核对的阶段脚本。** agent 能直接完成的步骤不放进向导。

## 核心工作流

### 1. 盘点人工步骤

先读 `.env.example`、README、容器配置、框架配置和 CI workflow。需要确认本机已有值时，只有用户明确授权才读取 `.env`；只提取键名和是否存在，遮盖值，禁止把 secret 写入报告、提示或提交。列出每个必须由人完成的阶段、阶段产物、值的来源、写入位置和是否为 secret。迁移或切换还要列出现状、目标和不可逆动作。

把阶段顺序和每个产物交给用户确认。用户可以增删或调整阶段；阶段未收口，不生成脚本。

### 2. 写出每阶段路径

为每个阶段写清：打开哪个 URL、点击什么、在哪看到值、填入哪个变量、是否隐藏输入、是否写入 `.env` 或 GitHub secret。不了解当前页面或命令时先查官方资料或向用户询问，不编造操作路径。

完成标准：陌生人只看阶段说明就能完成动作，且每个值都有来源和去处。

### 3. 生成向导

复制 [template.sh](template.sh) 到临时目录或用户指定的 `scripts/` 路径。只修改 `STAGES` 标记之后的区域：每个人工阶段写一个 `stage`，设置正确的 `TOTAL_STAGES`，使用模板提供的 `open_url`、`ask`、`ask_secret`、`write_env`、`set_secret`、`set_var`、`pause` 和 `confirm`。

- 打开 URL 后再要求粘贴值
- secret 使用隐藏输入
- 重跑保留已有环境值，写入操作保持幂等
- `write_env`、`set_secret` 和 `set_var` 在副作用前确认目标；GitHub 写入必须能识别明确的 `owner/repo`
- 其他不可逆动作前使用 `confirm`
- 一个阶段只做一个聚焦任务，避免用户需要滚屏找当前动作

不要修改模板标记之前的共享库。临时向导默认不提交；用户要重复使用时才保存在仓库并接入 README。

### 4. 静态验证

运行 `bash -n <script>`，有 `shellcheck` 时再运行它，并确认脚本可执行（`chmod +x <script>`）。静态核对每个阶段的产物是否写到第 1 步声明的位置，secret 名称是否与 CI 引用一致。需要行为冒烟时，使用临时 `ENV_FILE` 和假的 `gh` 命令验证幂等写入、目标仓库和拒绝确认分支，不连接真实账户。不要自己端到端运行向导，因为它会打开浏览器并等待人工输入。

### 5. 交付说明

说明脚本路径、运行命令、会写入的文件、跳过的人工动作和重新运行方式。可重复流程再补 README 链接；一次性流程完成后删除临时脚本。

## 默认授权

- 直接执行：读取非敏感仓库文件、列出阶段、生成脚本、运行语法检查
- 执行后告知：写入用户指定的脚本、`.env` 或开发配置
- 必须先确认：读取 `.env` 值、执行向导、写入真实 secret、执行不可逆迁移或对外账户操作
