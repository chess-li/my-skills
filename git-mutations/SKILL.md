# git-ops

## 意图锚点

git 写操作（commit/push/rebase/reset/branch -D/clean/rm）的授权边界 = 用户字面。用户没说的写操作不做；实际机制超出授权字面时先披露等确认。事后披露不能替代事前授权。

## 管辖判定

- 独立 git 任务（整理提交/迁移提交/推送/删除）→ 本 skill
- issue 驱动流程内的切片提交与 squash 合入 → implement（其正文有对应纪律），本 skill 不重复管辖
- 作业位置（worktree 建/迁/清）→ worktree skill

## 授权默认值

- 直接执行：只读操作（status/log/diff/show/ls-remote）与 fetch（不动工作区与本地分支）
- 字面授权即边界：用户说「提交」→ commit；说「整理并重新提交」→ 整理 + commit。push、改写历史、删除均不含在「提交」字面内
- 必须先问（question 裁定，意识到该问就问，不自我说服）：
  - push / force-push / 改写已存在历史（rebase -i、reset --hard、amend 已落基线的提交）
  - 删除分支（-D）、删除未跟踪文件/目录、clean -fd
  - 模糊指令（「整理并提交」「处理一下差异」）→ 动手前裁定三件事：范围（哪些提交/文件）、是否推送、整理粒度
- 机制偏差披露：实际机制超出授权选项字面（如授权「squash 单提交」实际用改写基线指针的 patch 式、追加 amend）→ 执行前披露机制，等确认

## 防护实践

- 改写历史前：建备份分支（`backup/<主题>-<日期>`）；交付前新旧树 `git diff` 空集校验（等价比对）
- 删除类命令先干跑预览（`git clean -nd`）；删除未跟踪文件/目录前向用户确认归属——它可能是他人或前会话产物
- 提交纪律：git add 用显式路径清单（不 add -A），提交前核对暂存区与任务一致
- 临时 worktree、诊断文件、备份目录自造自清，不进提交

## 交付口径

- 本地提交后未推送 → 明示「未推送，需要推送说一声」，不擅自推
- 交付声称与命令证据一致：推送区间、提交哈希、等价比对结果可核对
- 发现可疑产物（误生成目录、他人未提交改动）→ 不动 + 提示用户，不代为处置

## 工作流

1. **判管辖**：独立 git 任务 → 继续；implement 流程内 → 回 implement
2. **授权盘点**：用户字面覆盖哪些写操作；模糊 → question 裁定（范围/推送/粒度）
3. **防护**：改写历史 → 备份分支；删除类 → 干跑预览 + 归属确认
4. **执行**：显式路径 add、暂存区核对
5. **校验**：改写类做等价比对（`git diff` 空集）
6. **交付**：未推送声明、机制偏差披露、可疑产物提示
