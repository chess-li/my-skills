# 固定规则与验收标准

## 0. 两类规则的分工

本文件的规则分两类，执行者不同，不得混淆：

- **形式规则**（代码执行）：判定只看输入的形态——字段存在性、格式、数量、顺序、集合相等、路径存在，不需要理解内容。唯一可执行来源是 `templates/rules.json`，由 `scripts/rule_engine.py` 解释执行；不同业务替换该文件即可更换规则。本文件对形式规则只说明业务含义，不复述判定逻辑。
- **语义规则**（模型执行）：判定必须理解内容——研发实质、冲突取舍、政策适用、禁写措辞识别等。代码只能辅助（如占位符集合一致性兜底），不能裁决，由模型按本文件执行。

形式规则覆盖本节 §2 的时间顺序链、§3/§5 的 Hxx 编号与集合一致性；这些条款的强制校验失败时脚本直接拒绝输入，模型不得绕过。

## 1. 研发实质规则

项目必须尽量呈现：明确技术问题、研究目标、技术不确定性、试验/迭代过程、验证方法和成果。以下内容不能仅凭名称认定为研发：常规生产、简单配方或工艺变化、常规质量检测、维修维护、市场调研、单纯客户定制、商业化支持和直接套用公开成果。

如果材料同时包含研发和非研发活动，按活动边界拆分；不能把生产、销售或宣传结果整体写成研发成果。

## 2. 时间规则

> 形式部分（时间顺序链、日期格式、起止成对）由 `templates/rules.json` 的「时间顺序」「实际研发起止成对」规则强制，脚本直接拒绝违规输入；含 Hxx 的日期不参与比较。本节其余内容是语义规则，由模型执行。

时间逻辑必须满足：

`立项决议日 ≤ 实际研发开始日 ≤ 项目计划书编制日 ≤ 实际研发结束日 ≤ 成果效用说明日`。

“≤”允许同日。日期不全时保留 `Hxx`；日期冲突时列出各来源值和位置，不擅自选择。立项决议不得把事后成果写成决议时已知事实。

## 3. 一致性规则

> 形式部分（Hxx 占位符集合跨文件一致、编号连续）由 `templates/rules.json` 强制并在渲染后核验；冲突值的取舍是语义判断，由模型按本节执行。

至少逐项核对：项目全称、承担单位、项目负责人、研发周期、项目状态、研发目标、技术指标、研发人员、预算总额、费用分类、成果名称、专利/标准/报告编号、成果归属和应用结论。

同一字段跨文档只能有一个确认值。无法统一时：

1. 正文使用中性表述或 `Hxx`；
2. 工作底稿记录各来源值；
3. 补充信息清单要求用户确认；
4. 不用“以最终资料为准”掩盖冲突。

**裁决纪律**：模型不得代替用户在冲突值之间做选择。凡冲突字段会进入客户版正文，必须落 `【待核对：Hxx】` 或取得用户明确裁定；只把一侧值写进正文、仅在底稿留痕，属于掩盖冲突的流程违规。用户裁定（如"以实际为准"）只对裁定明确覆盖的字段生效，不自动扩展到其他冲突项。

## 4. 来源与数字规则

- 金额保留原币种、单位和小数位；不进行未经说明的单位换算；
- 指标保留样品、条件、时间、单位和检测方法；
- 检测报告、专利、标准和合同保留出具方、编号和日期；
- 经济效益必须写测算口径和数据来源；没有依据时不写数值；
- 图片中的数据只有在清晰可读并能定位时才可使用；经 OCR 识别的图片字段必须再读图核对并以图像为准，核对动作在工作底稿留痕；
- 每条关键事实在工作底稿中必须有“来源文件—位置—摘录/摘要”。

## 5. 占位符规则

> 形式部分（H 编号格式、唯一、连续、页码格式、Word 与清单集合一致、首次出现顺序）由 `templates/rules.json` 强制；占位文本怎么写、冲突怎么标注是语义规则，由模型按本节执行。

- 按 Word 首次出现顺序分配 `H01`、`H02`……；
- 同一待补事项在多处复用同一编号；不同事项不得共用编号；
- 占位文本必须说明要补什么，例如 `项目负责人【待补充：H01】`；
- 冲突事项用 `【待核对：Hxx】`，不要把冲突值猜成一个值；
- Word 和补充信息清单的 `Hxx` 集合必须完全相同；
- 一个 `Hxx` 只对应一项可执行事实，清单一行只记录一个待补事项。

## 6. 政策规则

研发费用归集、负面清单、委托/合作研发、费用比例和申报表规则可能随年度或地区变化。未完成当前适用政策核验时，不写具体税率、加计比例、表单字段或“肯定可享受”等结论。需要政策判断时，使用最新官方来源并在底稿记录来源和适用年度。

## 7. 客户版禁写内容

以下内容只进入内部工作底稿或补充信息清单，不进入三份客户版正文：

- “材料不足以证明”“税务风险高”“建议补证”“评分”“风险等级”“通过概率”；
- 证据链评分、审查意见、整改优先级、项目纳入/不纳入的内部裁决；
- 未经来源支持的绝对化宣传语，如“国际领先”“完全解决”“显著提升”。

## 8. 生成验收

- DOCX 目录与固定一级章节一致；
- 表格不越界，关键表头跨页重复，图片与图注可读；
- 计划书每条技术主线五要素齐全；
- 成果说明的实际成果与计划目标有映射；
- 立项决议不出现事后成果；
- 所有金额、日期、人员、指标、编号有来源或 `Hxx`；
- DOCX 与 XLSX 渲染后无空白页、截断、公式错误、失效筛选或孤立占位符。
