## 协议边界

模板是版式和插槽的来源，源数据是字段和证据的来源。模板中的自然语言只能作为辅助入口：先把它解析成显式协议，再由人或目标投影确认，最后才允许渲染。渲染器不猜测“某一段”“相关图片”或“适当位置”等语义。

第一版使用受限标记协议。字段路径只允许由字母、数字、下划线、短横线和点组成；条件只允许字段存在性或与 JSON 字面量比较；不允许调用函数、脚本、网络资源或任意表达式。

## 标记语法

规范形式如下：

```text
{{field:project.name}}
{{field:project.date|format:"YYYY-MM-DD"}}
{{field:project.owner|default:"未提供"}}
{{#if:project.approved}}
内容
{{/if}}
{{asset:image-001}}
{{attachment:appendix-001}}
```

- `field` 解析结构化字段；`format` 只能使用投影声明的格式器。
- `default` 是模板级默认值的书写形式，进入投影后与投影默认值合并；两处声明不同值时预检失败，不静默选择一处。
- `if` 只接受存在性或字面量比较；条件为假时删除整个条件块。
- 列表循环语法暂不属于第一版协议。出现 `{{#each:...}}` 或 `{{/each}}` 时预检失败，不把循环内容按普通文本猜测展开。
- `asset` 和 `attachment` 只引用资产清单中的 ID，具体模式由资产契约决定。

渲染完成后不得残留任何上述标记。未能解析的标记是阻塞错误。

## 自然语言辅助入口

自然语言只用于发现槽位和生成候选协议。候选必须先经过目标投影和证据台账确认，再写入模板；渲染器不会直接解释自然语言。

例如：

```text
“当 project.enabled 为真时保留下面一段，否则整段删除。”
→ {{#if:project.enabled}} … {{/if}}

“把 source.docx 的第 3 个正文段落放入项目说明。”
→ 模板：{{field:project.description}}
  投影：{"project.description":{"source":"evidence:e-003"}}
```

“相关图片”“某一段”“适当位置”等没有稳定定位或字段路径的说法不能直接渲染；必须先补成明确的锚点、证据 ID 和资产 ID。

## 锚点规则

- 每个需要填充的锚点有稳定 ID 或稳定字段路径；同一作用域内的唯一性由预检检查。
- 所有块标记必须成对出现，不能交叉嵌套；块起止标记不参与最终文本。第一版只有条件块可渲染，循环块即使成对出现也会预检失败。
- 条件块的开始和结束标记必须各自占据独立段落或表格单元格段落；把整块嵌入普通句子时预检失败。
- 图片和附件标记必须占据独立段落、表格单元格或明确的资产插槽；不把二进制内容塞入普通文本占位符。
- 标记被拆到多个 run、书签、文本框或形状中时，只有在能力矩阵明确支持该部件时才处理；否则预检失败并指出模板位置。
- 删除条件块后应清理空段落、孤立项目符号和空表格行；不能留下不可见占位痕迹。

## Word 部件能力矩阵

| 部件 | 第一版 | 规则 |
|---|---:|---|
| 正文段落 | 支持 | 字段、条件和图片插槽可用 |
| 表格单元格 | 支持 | 支持字段和条件；第一版不支持循环展开 |
| 页眉、页脚 | 支持 | 每个节独立解析，引用同一目标投影 |
| 脚注、尾注 | 不默认支持 | 出现标记时预检失败，除非适配器声明支持 |
| 文本框、形状、绘图层 | 不默认支持 | 不把视觉上可见的文本当作普通段落 |
| 域、批注、修订标记 | 不作为插槽 | 由 `word` skill 单独维护，不能隐式覆盖 |
| OLE、宏、外部嵌入对象 | 不默认支持 | 走附件关系契约；不支持时失败 |
