## 结构验证

结构验证应检查：

- 所有必需锚点均已解析，文档中没有残留标记；
- 条件块、循环块和目标表格的行数符合投影；
- 字段值、默认值和字段状态符合数据契约；
- 图片、附录和外部引用的关系目标存在，媒体类型和哈希一致；
- 每个需要证据的字段都能回指证据台账；过期证据不得通过；
- 原模板中声明保留的样式、节、页眉页脚和未触及部件没有断链。

随附渲染器报告中的 `package_passed` 只表示 DOCX 必要部件、内部关系目标、可重新打开和标记残留检查通过。字段状态、证据绑定、资产哈希由预检报告承担；表格语义、媒体尺寸、样式保真和版式仍需调用方按本节完成检查。结构验证通过不代表版式可交付。

包结构验证与 OOXML XSD 校验是两件事。若调用方额外运行 XSD 校验器，应分别记录输入模板的基线错误和本次渲染新增错误；不能把模板已有错误归因于渲染器，也不能把未运行 XSD 校验写成已通过。

## 视觉验证

在固定的本地渲染环境中把 DOCX 转为 PDF 和逐页图片，检查：

- 页数、分页和关键标题位置；
- 表格是否溢出、断裂或产生空白页；
- 图片是否缺失、变形、裁切错误或遮挡文字；
- 页眉、页脚、页码和字体回退；
- 条件块删除后是否留下空项目符号、空段落或孤立标题。

视觉一致采用结构化区域和允许的版式容差判断。字体抗锯齿、压缩元数据和 DOCX ZIP 顺序差异不构成失败；关键区域位置、内容和关系缺失构成失败。

## 运行清单

运行清单至少记录：

```json
{
  "run_id": "run-001",
  "template_sha256": "...",
  "projection_sha256": "...",
  "source_hashes": ["..."],
  "asset_hashes": ["..."],
  "renderer_version": "...",
  "status": "structural_ready",
  "used_defaults": ["project.owner"],
  "used_evidence": ["e-001"],
  "used_assets": ["image-001"],
  "structural_check": "package_passed",
  "visual_check": "not_run"
}
```

## 交付判据

模板渲染入口在预检、写出和结构检查通过后将状态标为 `structural_ready`。运行视觉验证入口后状态变为 `visual_ready`；人工检查逐页 PNG 后显式接受，才把 `visual_check` 从 `not_run`/`generated` 更新为 `passed` 并将状态标为 `rendered`。只有同时满足以下条件才算最终交付成功：

1. 预检没有阻塞项；
2. 目标 DOCX 可以重新打开，关系和内容类型完整；
3. 结构验证通过；
4. 视觉验证通过；
5. 运行清单和验证报告能够回指本次模板、投影、源文件和资产哈希。
