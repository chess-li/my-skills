# Skill 设计原理（创建与审查共用）

本文件收录**创建与审查两相通用**的原理：创建 skill 时它们是设计原则，审查 skill 时它们是审计标准——同一条原理，两顶帽子。迭代治理内容（证据闸、回归、冻结、移植、测试集）不在此处，见 skill-iteration-review。

根目标：**可预测性**——每次运行走同样的*过程*，而不是每次产出同样的文本。以下每条原理都是它的杠杆。

## 目录

1. 触发：description 与调用方式
2. 上下文：差值原则与优化顺序
3. 授权与默认值
4. Workflow 结构
5. 措辞与组织

## 1. 触发：description 与调用方式

- **先选调用方式**：需要 agent 自动触发（或需被其他 skill 调用），才保留 model-invoked 的 description——它每轮常驻上下文，是永久成本。只由人手动调用的 skill，去掉 description（user-invoked），零常驻成本，但人成为索引；手动 skill 多到记不住时，用一个 router skill 做目录。
- description 是触发决策唯一可见层。写**本质能力与判别边界**，不枚举用户说法（说法是无穷的）；症状表述只保留类别级锚点（≤4 个代表例）。
- 必须含**负向边界**："不用于 X，那是 Y skill 的事"——相邻 skill 之间靠它划界。
- 删掉正文已有的身份描述：description 只留触发信息和"当其他 skill 需要……"的可达性条款。

## 2. 上下文：差值原则与优化顺序

**差值原则**：skill 的首要责任是"唤醒"——在执行现场把注意力引向正确行为。模型能答出原则 ≠ 执行时会想起（回答被问题唤醒，执行只能被机制唤醒）。正文携带的知识量应精确等于"模型先验"与"期望行为"的差值，一分不多。

设计形态（创建时自问）与审计形态（审查时逐段问）是同一组问题：

1. 没有这句，模型也会做对吗？ → 删（纯稀释；即 no-op 测试：它改变默认行为吗）
2. 模型知道但会忘？ → 留，压成清单式短句（唤醒 + 差值）
3. 模型不知道？（私有约定、负向边界、历史教训）→ 留，写成明确知识
4. 必须每次精确一致？ → 挪进 scripts（确定性不靠注意力保证）

**空钩子无效**："注意质量"类纯提醒不含差值，等于没写；有效唤醒必须附带压缩的操作信息。想要更强行为，换锚定力更强的词，不要加更多句子（选词双闸见第 5 节「措辞与组织」）。

**优化顺序（拆分排最后）：**

1. 删减：删掉模型本来就知道的解释、通用知识、礼貌性说明
2. 压缩：散文压成规则，规则压成示例——一个好示例胜过十句说明
3. 脚本化：确定性重复操作挪进 scripts/，内容不再进入上下文
4. 拆 references：仅对典型任务中 <30% 概率用到的条件化内容；指针的**措辞**决定 agent 能否找到它，找不到时先磨措辞再考虑挪回正文
5. 拆成独立 skill：仅当拆出部分有独立触发场景，或**后续步骤的可见性诱使 agent 草率完成当前步骤**——先磨利完成判据，判据实在无法清晰且确实观察到抢跑，才用拆分藏起后续步骤

## 3. 授权与默认值

- 显式三档授权清单：默认直接执行（读取、分析、草稿）；执行后告知（低风险写操作）；必须先确认（删除原始文件、对外发送、付费操作）。破坏性操作的确认保留并写明。
- 所有常见决策点写死默认值（"未指定格式时默认输出 xlsx"）——未指定的选择是门禁最大的诱发源。
- 对冲措辞（"建议/可以/考虑"）改为祈使句。

## 4. Workflow 结构

- **锚定产物，不锚定状态**：每步以可观察的文件或结果为完成判据（"cleaned.xlsx 存在且行数一致"），可断言、可检查、支持断点续跑。判据要可检验，关键处要穷尽（"每个修改过的模型都有交代"，而非"产出一份清单"）——模糊的判据诱发草率完成。
- **一条主干，拒绝图结构**：happy path 压成 ≤7 步线性清单；分支只在后续做法真正不同的决策点出现，写成短选项。
- **恢复规则只写一条**："回到上一个可验证产物重来"，不枚举每种失败的转移路径。
- **刚性只给脆弱点**：大部分步骤给启发式自由度，仅易错、不可逆步骤锁死参数。
- **状态机归脚本**：状态确实复杂、转移必须精确时，执行者该是代码而非注意力——实现在 scripts/ 里。

## 5. 措辞与组织

- **选词过双闸**：招募是必要非充分——招错比不招更危险，不招只是贵（付定义成本），招错会把行为锚到错意象上。
- **闸一·招募共识吗**：先用模型知识 / 行业共识 / 社区共识 / 大众共识里已有的概念，越宽越好；好的主导词几个 token 换一整片规则，行为锚点更稳。自造词不招募先验，是最后手段；一旦造词，定义必须显式写进正文，不靠读者会意。
- **闸二·招来的干净吗**：先验是打包带来的，联想必须恰好等于所需含义——清晰、明确、无隐藏含义、无副作用（"闸"夹带二元开合、"雾战"夹带游戏腔，都是副作用）。
- 祈使句；**禁令必须配正向目标**——纯否定会把被禁行为激活（"别想大象"），说明该做什么，让被禁的不必被点名；只有无法正向表述的硬护栏才保留禁令，且与正向目标成对出现。
- 单一信源：每个含义只在一个权威位置出现，改动只改一处；重复表述会抬高该含义的显著性，超过其真实权重。
- 共置：一个概念的定义、规则、注意事项放在同一标题下，读其一处自带上下文。
- 大文件（>100 行）开头放目录。
