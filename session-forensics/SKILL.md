# 会话取证

本 skill 守护一条主线：**可复核性**——每个结论都能回到会话库的一手记录（用户原话、工具序列、reasoning），不靠印象复述。产物是证据包，不是感想。

## 核心工作流

### 1. 定问题与范围

写下要回答的问题、时间窗或目标会话、产物去向（周期复盘找模式 / 单会话调查 / 核实完成声称）。问题不清楚时问用户一次，不边查边猜。

### 2. 立取证通道

取证通道 = harness 适配器：脚本 `--harness` 选择（默认 auto；多家 harness 并存时按取证对象显式指定，不默认真人输入来自本 harness）。各 harness 的存储位置、格式与已知坑各有一份 reference——处理哪家读哪家：OpenCode 读 [references/opencode-schema.md](references/opencode-schema.md)，Codex 读 [references/codex-rollout.md](references/codex-rollout.md)。存储格式随 harness 版本漂移：适配器内置守卫，格式与预期不符即大声失败并指向对应 reference，不静默返回可疑数据；守卫报障时实查实际格式，更新 reference 与适配器。未覆盖的 harness：先定位其会话存储、核实格式、落一份新 reference，再加适配器——不凭记忆写提取器。不重新执行会话中的命令，不修改任何会话数据。

### 3. 提取与过滤

用户消息全量提取；脚本只剔空消息，注入形态（system-reminder、environment_context、AGENTS.md 注入等，两家 harness 都有）靠人工剔除，各 reference 的已知坑列有形态清单。assistant 侧抽样读——首条（方法规划）、关键中间条、末条（交付总结），不全读。统计面用聚合查询（会话数、工具分布、轮次、异常收尾），不逐条数。固定提取动作走脚本：

```bash
python3 "<session-forensics skill directory>/scripts/session_extract.py" <子命令> --help
```

### 4. 回放与对账

大范围复盘派并行回放子代理：每个代理只取证、返回可复核事实（会话 ID、消息锚、原话摘录），不下最终裁决；裁决留主会话。子代理线索核实后才作证据。所有「声称」与一手证据对账——用户原话、`git log -S`、文件实测。判断类问题（为何没加载某 skill、为何没问用户）先查 reasoning 部件确认判断事件是否发生，再下结论。

作为 agent 问题证据的事件，按时间核对介入前动作、用户介入和介入后结果；区分产品既有缺陷、被制止的建议与实施后的返工，另标每项证据的核实状态。

### 5. 诊断到机制层

每个模式归并到机制层一句话：病灶在哪一层（触发锚点、授权默认值、完成物错锚、双事实源……），为什么模型会犯。写不出机制句的模式是症状收集，回第 4 步补取证。证据不足的候选不升格，进观察名单。

### 6. 收口闸

每次取证必须收口为以下至少一种产物，零产物报告视为未完成：

- 返工事件草稿（日期 | 对象 | 症状 | 疑似病灶层），追加进 `skill-证据日志.md`
- 观察名单条目（含拉动条件）
- 升格提案（交 skill-creator 管线，由用户一字批准）
- 拒绝清单（明确不做什么、理由是什么）

✅ 「模式 X 有 3 起实例（ses_a/ses_b/ses_c），机制句一句话，建议升格提案交用户裁定」
❌ 「整体表现良好，建议继续保持」——无产物、无锚点

取证对象是项目行为而非 skill 时，产物按 research skill 的入口约定落 `docs/research/`。写入文件执行后告知用户。

### 7. 交付检查

逐条核对：每个结论有会话 ID 与消息锚；统计口径开场与收口一致，不一致处显式说明；作证据的子代理线索已核一手原文（核实规则单一信源是第 4 步）；未核实项标「未验证」及原因，不写成事实。周期复盘按 harness 报告候选会话数、过滤规则、用户消息实际提取覆盖及未覆盖范围；未完成全量提取时标「未完成」，不把筛选结果写成全量结论。Codex 按首次创建日期过滤可能漏掉窗口内恢复的旧会话，报告该缺口，除非已另行覆盖。

## 默认授权

- 直接执行：只读查询会话库与 git、派回放子代理、统计聚合、起草证据包
- 执行后告知：追加证据日志、落 `docs/research/` 研究文件
- 必须先确认：升格提案（用户一字批准）、修改 skill 正文（归 skill-creator）、对外发布复盘结论
