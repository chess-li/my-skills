# 变更种类验证

## 读取条件

编写或更新验收标准时，若变更包含新增、修改、移除或改名/迁移行为，spec 读取本文件，并把对应核对写进验收标准。不把本文件复制进 spec。

implement 验证这些变更时读取。code-review 评审这些变更时读取。不涉及行为去留的改动不读。

## 核对

- 新增：验证新行为可达。
- 修改：验证新结果，并验证仍承诺的旧行为仍可用。
- 移除：反查旧行为不再暴露。明确承诺的兼容要保留，并验证该兼容仍在。
- 改名或迁移：从基线确认原行为曾经存在，再验证目标名称或位置上的契约。不要求所有代码符号同步改名。

## 状态

- 不适用：写 `not-applicable`，并写原因。
- 适用但没有证据：写 `not-verified`。不要写成通过。
- 缺少基线：写证据缺口。不要把缺口写成 `not-applicable`。

新增路径成功，不能单独证明移除、修改或迁移后的承诺成立。
